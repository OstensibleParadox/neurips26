
## 🚀 **快速配置 SSH（无需再输 Token）**

### **步骤1：将 SSH 密钥添加到 ssh-agent**

```bash
# 应该看到：Agent pid XXXX
```

## 🔧 **一键配置脚本**
```bash
#!/bin/bash
# 保存为 fix-git-auth.sh，然后运行：bash fix-git-auth.sh

echo "🔧 正在修复 Git 认证配置..."

# 1. 停止使用 HTTPS 凭据
git config --global --unset credential.helper

# 2. 确保 SSH 代理运行
eval "$(ssh-agent -s)" > /dev/null

# 3. 添加 SSH 密钥
ssh-add --apple-use-keychain ~/.ssh/id_ed25519 2>/dev/null

# 4. 测试 SSH
echo "🧪 测试 SSH 连接..."
ssh -T git@github.com 2>&1 | grep -q "successfully authenticated" && echo "✅ SSH 配置成功！" || echo "❌ SSH 配置失败，请检查公钥是否添加到 GitHub"

# 5. 修改当前仓库 URL（如果是 HTTPS）
current_url=$(git remote get-url origin 2>/dev/null)
if [[ $current_url == https://* ]]; then
    echo "🔄 检测到 HTTPS URL，正在转换为 SSH..."
    user_repo=$(echo $current_url | sed 's|https://github.com/||; s|\.git$||')
    git remote set-url origin "git@github.com:$user_repo.git"
    echo "✅ 已转换为 SSH URL"
fi

echo "🎉 配置完成！现在可以不用 Token 操作 Git 了。"
```

## 🔐 **SSH vs Token（HTTPS）的本质区别**

### **SSH 密钥认证（类似"物理钥匙"）**
```bash
# 工作原理：非对称加密
ssh-keygen -t ed25519  # 生成一对密钥
# 私钥：~/.ssh/id_ed25519（保存在本地，永不外传）
# 公钥：~/.ssh/id_ed25519.pub（上传到 GitHub）
```

**特性：**
- ✅ **一次配置，永久使用**（除非密钥被撤销）
- ✅ **最安全**（私钥从不上传，理论上无法破解）
- ✅ **自动认证**（配置好就不用再管了）
- ✅ **支持所有操作**（push/pull/clone 等）
- ⚠️ **需要初始配置**（生成密钥、上传公钥）
- ⚠️ **每台设备需要单独配置**（每台电脑有自己的密钥对）

### **Personal Access Token（HTTPS）（类似"临时密码"）**
```bash
# 工作原理：密码替代品
https://github.com/用户名/仓库.git
# 用户名：你的 GitHub 用户名
# 密码：使用 Token 替代
```

**特性：**
- ✅ **容易生成和撤销**
- ✅ **可以设置细粒度权限**（只读 repo、写 repo、删 repo 等）
- ✅ **支持双重认证账户**
- ❌ **有有效期**（默认过期或可设置过期时间）
- ❌ **需要存储和管理**（存在钥匙串或配置文件中）
- ❌ **可能泄露**（如果保存在配置文件中）

## 🏗 **技术架构对比**

| 方面 | SSH 密钥 | Token（HTTPS） |
|------|---------|---------------|
| **协议** | SSH 协议（端口 22） | HTTPS 协议（端口 443） |
| **认证方式** | 非对称加密（公私钥对） | 密码学令牌（字符串） |
| **存储位置** | 私钥本地，公钥远程 | Token 本地+远程生成 |
| **过期时间** | 永久有效（除非撤销） | 可设置过期时间 |
| **多设备** | 每台设备需要独立密钥 | 同一 Token 可用于多设备 |
| **企业网络** | 可能被防火墙阻挡 | 通常都允许（HTTPS） |
| **安全性** | 极高（私钥不离开设备） | 高（但 Token 可能泄露） |

## 🔄 **如何选择？**

### **选 SSH 如果：**
1. 你是**个人开发者**，在自己的电脑上工作
2. 你**讨厌每次输入密码/Token**
3. 你想要**最高级别的安全**
4. 你的网络**允许 SSH 连接**
5. 你愿意**花5分钟配置一次**

### **选 Token（HTTPS）如果：**
1. 你在**企业网络**，防火墙可能限制 SSH
2. 你需要**精细的权限控制**（只读、只写等）
3. 你在**临时设备**上操作
4. 你需要**自动过期**的安全策略
5. 你使用**双重认证**，且不想配置 SSH

## 📊 **安全对比深度分析**

**SSH 的安全优势：**
- 私钥**永远不出你的电脑**
- 即使 GitHub 被黑，攻击者也无法冒充你
- 可以设置**密钥密码**（加密私钥）

**Token 的安全风险：**
- Token 会**在内存、配置文件、日志中出现**
- 如果电脑被入侵，Token 可能被盗
- 需要在多设备间**安全地传输 Token**

- 几乎所有现代 Git 工具都支持 SSH
- GitHub、GitLab、Bitbucket 都强烈推荐 SSH

## 🔄 **完全重置 SSH 配置（干净重来）**

### **步骤1：备份现有配置（可选但推荐）**
```bash
# 创建备份目录
mkdir -p ~/.ssh-backup-$(date +%Y%m%d)

# 备份所有 SSH 文件
cp -r ~/.ssh/* ~/.ssh-backup-$(date +%Y%m%d)/
```

### **步骤2：完全删除现有 SSH 配置**
```bash
# 1. 停止所有 ssh-agent 进程
killall ssh-agent 2>/dev/null

# 2. 删除整个 .ssh 目录（最彻底的方法）
rm -rf ~/.ssh

# 3. 从钥匙串中删除所有 SSH 相关项目
security delete-generic-password -l "ssh" /Users/$(whoami)/Library/Keychains/login.keychain 2>/dev/null
security delete-generic-password -l "SSH" /Users/$(whoami)/Library/Keychains/login.keychain 2>/dev/null

# 4. 清理 Git 全局配置中的 SSH 设置
git config --global --unset core.sshCommand 2>/dev/null
```

### **步骤3：创建全新的 SSH 配置**
```bash
# 1. 重新创建 .ssh 目录（正确权限）
mkdir -p ~/.ssh
chmod 700 ~/.ssh

# 2. 生成全新的 SSH 密钥（Ed25519，最安全）
ssh-keygen -t ed25519 -C "你的邮箱地址" -f ~/.ssh/id_ed25519

# 按提示操作：
# - 直接回车使用默认路径
# - 输入一个密码（建议设置，更安全）
# - 确认密码

# 3. 设置正确的文件权限
chmod 600 ~/.ssh/id_ed25519
chmod 644 ~/.ssh/id_ed25519.pub

# 4. 创建配置文件
cat > ~/.ssh/config << EOF
# GitHub
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519
    AddKeysToAgent yes
    UseKeychain yes
    IdentitiesOnly yes

# 可以添加其他 Git 服务
# Host gitlab.com
#     HostName gitlab.com
#     User git
#     IdentityFile ~/.ssh/id_ed25519
EOF

chmod 600 ~/.ssh/config
```

### **步骤4：配置 SSH 代理**
```bash
# 1. 自动启动 ssh-agent（添加到 shell 配置）
if [ -z "$SSH_AUTH_SOCK" ]; then
   # Check for a currently running instance of the agent
   RUNNING_AGENT="$(ps -ax | grep 'ssh-agent -s' | grep -v grep | wc -l | tr -d '[:space:]')"
   if [ "$RUNNING_AGENT" = "0" ]; then
        # Launch a new instance of the agent
        ssh-agent -s &> /dev/null
   fi
   eval "$(ssh-agent -s)" > /dev/null
fi
```
