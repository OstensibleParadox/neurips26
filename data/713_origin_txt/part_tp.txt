A.5 Experimental Parameters
A.6 Accessibility Statement
We designed the validation framework with accessibility as a
core constraint:
• Stage 1 (theoretical) and Stage 2 Pathway A (consumer
hardware) are executable on a laptop with 16GB+ RAM,
ensuring independent researchers, civil society organiza-
tions, and under-resourced regulatory bodies can verify
results without institutional compute budgets.
• Stage 3 Pathway B requires HPC resources but produces
artifacts (divergence scores, CSV files) that can be inde-
pendently verified. We release all intermediate outputs to
enable verification without re-running expensive experi-
ments.
• Quantized Models: Stage 2 uses Q4_K_M quantized
models via Ollama, reducing memory requirements from
16GB+ to under 8GB per model while preserving behav-
ioral signatures relevant to governance auditing.
Note on LLM Sampling Stochasticity. Stage 2 experiments
deliberately do not fix random seeds for LLM sampling be-
cause inter-trial variance 𝜎(𝒜) is itself a diagnostic signal.
The experimental design measures behavioral stability under
identical prompts with varying random draws—fixing seeds
would eliminate the variance we seek to measure.
This dual-pathway design ensures governance auditing tools
remain accessible to the full range of stakeholders—from well-
resourced regulators to independent watchdog organizations—
while industrial-scale validation pathways remain available
for comprehensive coverage.

Appendix B: Reference Implementation
The diagnostic framework described in this paper is supported
by a reference implementation available at https://anonym
ous.4open.science/r/recursive-lines-F6D8. The repository
provides:
Measurement Infrastructure:
• gpu_driver_test.py: Monte Carlo phase space valida-
tion (Stage 1: 250,000 synthetic trajectories)
• bandwidth_analyzer.py: Entropy and compression met-
rics (Stage 1 support)
• drift_monitor.py: Graph centrality analysis (Stage 1
support)
• exp1_agency_phase_transition.py: Empirical phase
mapping (Stage 2: consumer hardware, 100 trials/model)
• exp2_training_fork_divergence.py: Training fork
analysis (Stage 3: HPC, Base/Instruct model pairs)
• exp3_graph_triangulation.py: CMI/SRD triangula-
tion (Stage 2 cross-validation)
• novel_thermodynamics.py: Shannon entropy and
compression-based complexity metrics
Methodological Documentation:
• 26 documented methods across 8 categories (neural em-
bedding, graph analysis, information theory, thermody-
namic simulation)
• 79 interdisciplinary concepts embedded in test corpus
across 7 knowledge regions
• MD5 checksums and seed configuration for exact repro-
ducibility
Accessibility and Reproducibility:
Stage 1 (theoretical) and Stage 2 Pathway A (consumer hard-
ware) experiments are executable on Apple M4 Max (64GB)
or equivalent. Stage 3 Pathway B experiments require HPC
resources but produce artifacts (divergence scores, not model
weights) that can be independently verified. This design en-
sures governance auditing tools remain accessible to indepen-
dent researchers, civil society organizations, and regulators
without institutional compute budgets, while industrial-scale
validation pathways remain available for regulatory bodies.
We release all code, configuration files, and intermediate
outputs under permissive license. The empirical validation
(Stage 2) represents proof-of-concept on consumer hardware;
future work will extend to industrial-scale model coverage
pending compute access.
See repository documentation (docs/methodologies.md,
docs/field-knowledge.md, REPRODUCIBILITY.md) for
complete technical specification.
