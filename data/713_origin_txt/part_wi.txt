### 2. Theoretical Framework: Agent Architectures as Control Mechanisms

Prior work has established a tripartite taxonomy of agent architectures, each corresponding to distinct modes of control and oversight:

| Architecture | Control Mechanism | Alignment Analogue |

### 3. Plan-Then-Act Failure: The Brittleness of Constitutional Assumptions

The OpenClaw development team, like many agent platform creators, adopted an implicit **Plan-Then-Act governance model**. This approach mirrors Constitutional AI, wherein static rules are expected to govern behavior across all deployment scenarios.

The assumptions included:

- Users will enable authentication mechanisms
- Users will deploy behind reverse proxies or firewalls

The failure mode is characteristic of Plan-Then-Act architectures: **brittle overconfidence in the initial specification**. The real-world deployment environment diverged from the idealized model, producing configurations that satisfied local constraints (ease of deployment, rapid prototyping) while violating global security requirements. The constitutional rules, however well-intentioned, could not adapt to this divergence.

### 4. ReAct Failure: Myopic Optimization Without Global Constraints

Once deployed, OpenClaw instances operate in a loop structurally identical to the ReAct paradigm:

```

```

The runtime optimizes for task completion, interpreting and executing user instructions without reference to system-level safety boundaries. ```

The agent, following its design imperative, obediently executes instructions. The system has no mechanism for **policy verification** or **risk assessment** at the action level. This is the ReAct pathology of myopia manifested at the security boundary: locally correct execution enables globally catastrophic outcomes.
