       1. Convert covariance C to correlation R by R[i][j] = C[i][j] / (sigma_i * sigma_j)
       2. Eigendecompose R, clip negative eigenvalues to 0
       3. Reconstruct R+ = Q * diag(max(lambda_k, 0)) * Q^T
       4. Re-normalize: R+[i][j] /= sqrt(R+[i][i] * R+[j][j])

       - Should zero-variance dimensions participate in couplings at all?
       - How should the PSD projection handle a partially degenerate covariance matrix?

### 既定事实

`eigenEngine.js` 中的 `computeEigenstructure(estate)` 方法会从某个产权体的 7 维范围构建一个协方差矩阵。目前是对角矩阵（朴素实现）。我们正在向产权体 schema 中添加可选的 `dimensionCouplings`，用于填充非对角线条目：

```json
  }

```

## 四个待分解的缺陷

### 缺陷 1：零方差维度导致除零错误

当某个维度的范围为 `[a, a]`（例如 PRC 土地的 alienation = `[0,0]`）时，`sigma_i = 0`。  
相关转换 `R[i][j] = C[i][j] / (sigma_i * sigma_j)` 会除以零。整个相关空间投影变得不可解。

这不是假设——PRC Eigentum 土地的 alienation 和 inheritability 都是 `[0,0]`。

**子问题：**
- 零方差维度的协方差行/列应该是什么？
- 零方差维度是否应该参与任何耦合？
- PSD 投影应如何处理部分退化的协方差矩阵？
- 如果某个耦合引用了零方差维度，会发生什么？

### 缺陷 2：符号约定在形式上未定义

方案中说，相关符号编码了“维度值是同向变动（+）还是反向变动（-）”。  
但相关性是关于**协**变，而不是绝对水平的对比。  
fee_tail 的 alienation 较低 `[0,10]`，inheritability 较高 `[70,90]` —— 它们处于相反的绝对水平。  
但在该产权体的教义空间内，它们是否**协**变？符号 `-0.9` 是基于水平对立设定的，但这混淆了两种不同的事物：

- **水平对立**：alienation 低而 inheritability 高（静态事实）
- **协变**：一个在其范围内向上波动时，另一个是否向下波动？（动态事实）

协方差条目 `C[i][j] = rho * sigma_i * sigma_j` 编码的是二阶矩结构。在没有显式潜因子模型的情况下，符号赋值是解释性的，而非数学性的。

**子问题：**
- 什么样的潜模型（如果有的话）能为产权体特定的耦合符号赋值提供依据？
- 是否存在一种原则性的方法，从教义知识中确定符号？
- 我们是否应该区分“这些维度在结构上相关”与“这些维度以特定方向协变”？
- 符号对特征值的大小是否重要？（不影响特征值大小，但会影响特征向量的方向）

### 缺陷 3：Schema 中 ±1.0 的矛盾

校准规则说：“保留 ±1.0 用于真正的定义恒等”。  
验证规则说：“相关性必须在 `(-1, 1)` 内 —— 排除端点”。  
这两者相互矛盾。要么 ±1.0 被允许作为例外值，要么完全禁止。

**子问题：**
- ±1.0 是否会使协方差矩阵奇异？（是的 —— 会造成秩亏）
- 奇异性在这里真的有害吗？
- 验证规则的正确边界应该是什么？

### 缺陷 4：两个脆弱的测试

**测试 6.8**（“fee tail 符号正确性”）断言：存在一个特征向量，其中 alienation 和 inheritability 两个分量的大小都 > 0.2，且符号相反。  
这不是一个稳定的谱不变量 —— 特征向量由整个矩阵决定，而不是由单个教义对决定。其他耦合或校准值的微小变化可能导致该测试失败，而没有任何数学上的错误。

类似地，“验证主主轴反映了限定结构”是一种语义上的期望，而不是谱上的保证。

- 哪些合成测试用例能给出确定性、可解析预测的特征系统？

 Context

 computeEigenstructure(estate) builds a diagonal 7x7 covariance matrix from per-dimension uniform
 variances. Eigendecomposition of a diagonal matrix is trivially variance ranking — eigenvalues are
 the diagonal entries, eigenvectors are standard basis vectors. No cross-dimensional structure is
 revealed.

 To make single-estate eigenstructure non-trivial, we need off-diagonal covariance entries encoding
 doctrinal dimension couplings. This PR adds an optional dimensionCouplings schema to estate data and
  modifies the engine to consume it with proper PSD enforcement.

 Audit Corrections Incorporated

 1. PSD validity: Pairwise correlations in [-1, 1] do NOT guarantee a valid covariance matrix.
 Symmetry is automatic; positive semidefiniteness is not.
 2. PSD projection must reconstruct: Clamping eigenvalues alone is insufficient. Must reconstruct

 Sign convention: The sign of correlation encodes co-variation direction, not absolute level
 contrast. The question is: "within this estate's uncertainty band, if dimension A fluctuates toward

 flagged as dormant in the computation result.

 Step 4: Engine modification — eigenEngine.js

 4a: Add validateCouplings(couplings) (private)

 - Check each entry has valid dimensions, correlation in [-1, 1] (closed), non-empty doctrine
 - Detect duplicate unordered pairs -> throw RangeError
 - Return validated array (or empty array if input is undefined/null)

 4b: Add buildCovarianceMatrix(estate) (private)

 1. Build diagonal matrix from uniformVariance per dimension (current behavior)
 2. If dimensionCouplings present, call validateCouplings
 3. For each coupling {dimensions: [A, B], correlation: rho}:
   - sigma_i = sqrt(uniformVariance(estate.ranges[A]))
   - sigma_j = sqrt(uniformVariance(estate.ranges[B]))
   - C[i][j] = C[j][i] = rho * sigma_i * sigma_j
 4. Return the Matrix object

 4c: Add ensurePSD(covarianceMatrix) (private)

 Uses partition-and-embed for zero-variance dimensions, then single-shot correlation-space projection
  on the active submatrix (not naive eigenvalue clipping — see Higham 2002).

 1. Extract sigmas = sqrt(diagonal of covariance)
 2. Partition dimensions into active set A = {i : sigma_i > 1e-12} and frozen set F = complement
 3. Eigendecompose the full covariance matrix
 4. Check if any eigenvalue < -epsilon (epsilon = 1e-10 for numerical noise)
 5. If all eigenvalues >= -epsilon: return {matrix, eigenpairs, projected: false, frozenDimensions:
 F}
 6. If any eigenvalue < -epsilon:
 a. Extract the |A| x |A| active submatrix C_A from the covariance
 b. Convert C_A to correlation: R[i][j] = C_A[i][j] / (sigma_i * sigma_j) — all sigmas positive, no
 division by zero
 c. Eigendecompose R
 d. Clip negative eigenvalues to 0
 e. Reconstruct R+ = Q * diag(max(lambda_k, 0)) * Q^T
 f. Re-normalize: R+[i][j] /= sqrt(R+[i][i] * R+[j][j]) — forces diagonal to 1.0
 g. Convert back to active covariance: C_A+[i][j] = R+[i][j] * sigma_i * sigma_j
 h. Re-embed C_A+ into the full 7x7 matrix (frozen rows/columns remain zero)
 i. Re-decompose the restored full covariance matrix
 j. Return {matrix: C+, eigenpairs: new, projected: true, frozenDimensions: F}

 4d: Modify computeEigenstructure(estate)

 assertEstate(estate)
 covarianceMatrix = buildCovarianceMatrix(estate)
 {matrix, eigenpairs, projected} = ensurePSD(covarianceMatrix)
 // eigenpairs already sorted by sortEigenpairs inside ensurePSD
