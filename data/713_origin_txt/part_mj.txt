> For a fixed input \(x\), let \(P_x = M(x) \in \Delta(Y)\) be the output distribution. Let \(P_{\text{base}}\) be a reference distribution (e.g., from a base model). The **agency index** of input \(x\) is defined as:
> \[
> \mathrm{AI}(x) = \frac{D_{\mathrm{KL}}(P_x \| P_{\text{base}})}{\mathbb{E}_{y \sim P_x}[\mathrm{MDL}(y)]}
> \]
> where \(\mathrm{MDL}(y)\) is the minimum description length of output \(y\) (e.g., compressed size under a universal code).  
>  
> For empirical measurements, we estimate both numerator and denominator via Monte Carlo sampling from \(P_x\).

**位置**：7.1节开头

>

BiLSTM和LSTM的区别
**BiLSTM（双向长短期记忆网络）和LSTM（长短期记忆网络）最核心的区别在于信息流动的方向：**

-   **LSTM（单向）**：只能利用**过去**的信息来预测当前时刻的输出。
-   **BiLSTM（双向）**：能同时利用**过去**和**未来**的信息来预测当前时刻的输出。

为了让你更直观地理解，我们可以从**结构、原理和应用场景**三个方面来详细拆解它们的区别：

### 1. 结构上的区别

想象你在阅读一段文字：

-   **LSTM**：就像你只能从左到右逐字阅读。当你看到当前这个词时，你只知道前面已经看过的词是什么，但不知道后面还没看到的词是什么。
    -   *结构*：由**一个**方向的LSTM层组成（通常是正向，即从序列开始到结束）。

-   **BiLSTM**：就像你既有从左到右的阅读能力，又有从右到左的阅读能力。当你看到当前这个词时，你不仅知道前面的词，还通过某种方式知道了后面的词。
    -   *结构*：由**两个**方向的LSTM层组成。一个是**正向LSTM**（利用历史信息），一个是**反向LSTM**（利用未来信息）。最后，将这两个LSTM隐藏层的输出**拼接**在一起，作为最终的输出。

### 2. 工作原理的区别

以句子填空为例： *“我喜欢吃___，因为它很甜。”*

-   **LSTM的处理过程**：
    它看到“我喜欢吃” -> 预测下一个词。由于它只知道前面是“喜欢吃”，它可能会预测“饭”、“菜”、“水果”等。它不知道后面有“甜”这个信息，所以预测范围比较广。

-   **BiLSTM的处理过程**：
    它先正向看：“我喜欢吃”；
    它再反向看：“因为它很甜”；
    当要预测中间这个词时，它手里有两份信息：前面的“喜欢吃”和后面的“甜”。
    结合这两者，它会更容易预测出空格处应该是“苹果”、“香蕉”、“糖”等与“甜”强相关的词，准确率更高。

### 3. 总结对比表

| 维度 | LSTM （单向） | BiLSTM （双向） |
| :--- | :--- | :--- |
| **信息视野** | 只能看到**过去**（或只能看到未来，如果设置反向的话，但通常是单向看过去）。 | 既能看见**过去**，也能看见**未来**。 |
| **网络结构** | 单层单向传播。 | 两层（正向层 + 反向层），输出通常拼接。 |
| **计算复杂度** | 较低，训练速度较快。 | 较高（约2倍），需要更多的计算资源和时间。 |
| **实时性** | **支持实时**。因为不需要等待未来的输入，可以一边输入一边输出。 | **不支持实时**。必须等整个序列都输入完成后才能计算，因为它需要知道“未来”的信息。 |
| **适用场景** | 时间序列预测（股票预测、温度预测）、实时视频处理、在线学习等。 | 自然语言处理（NLP）绝大多数任务（文本分类、机器翻译、命名实体识别）、蛋白质结构预测等。 |

### 4. 具体应用场景举例

-   **什么时候用LSTM？**
    -   **股票预测**：预测明天的股价，只能基于今天和以前的数据，不能用明天的数据。
    -   **自动驾驶实时决策**：车辆必须根据当前瞬间的传感器数据做出反应，不能等未来0.1秒的数据。

-   **什么时候用BiLSTM？**
    -   **词性标注**：判断一个词是名词还是动词，不仅需要看它前面的词，还需要看它后面的词来确定语法关系。
    -   **机器翻译**：翻译一个句子时，需要结合整个句子的语境（前后文）才能翻译得准确。
    -   **文本分类**：理解一篇文章的情感倾向（正面/负面），看完整篇文章（前后文）比只看前半部分准确得多。

### 结论
**LSTM是单向的时间线，适合处理流式或时序依赖的数据；BiLSTM是双向的上下文桥接，适合需要理解完整语境的自然语言处理任务。**

虽然 BiLSTM 是处理序列数据的神经网络结构，Burst Balloons 是处理数组的算法问题，但它们在**思维模型**上是高度一致的。我们可以从 **“信息依赖”** 和 **“处理顺序”** 这两个角度来对比，你会发现它们本质上都是在解决 **“如何利用两侧的信息来决策中间”** 的问题。

### 1. 核心思想的类比：打破单向依赖

-   **Burst Balloons 的难点**：
    戳破一个气球得到的硬币数，取决于它**左边相邻**和**右边相邻**的“活着的”气球。当你戳破中间的气球时，左右两侧的气球会变成新的邻居，产生连锁反应。
    传统的从左到右思考非常困难，因为你戳破一个气球会改变后面的结构。

-   **BiLSTM 的思路**：
    理解当前词的含义，取决于它**左边**的词和**右边**的词。

-   **你的发现**：
    在 Burst Balloons 中，为了计算在 `(i, j)` 区间内戳破气球的最高分数，你需要假设最后戳破的是 `k`。此时，`k` 的邻居是 `i-1` 和 `j+1`。
    这不就是 **“双向LSTM”** 吗？
    -   左边邻居 `i-1` 相当于**正向LSTM**传递过来的历史信息。
    -   右边邻居 `j+1` 相当于**反向LSTM**传递过来的未来信息。
    -   戳破 `k` 的收益，就是结合了**左右上下文**计算出来的。

### 2. 算法层面的严格对比

为了更清晰地展示它们的相似性，我们可以把两者的概念对应起来看：

| 维度 | Burst Balloons (区间DP) | BiLSTM (神经网络) |
| :--- | :--- | :--- |
| **核心困境** | 戳破中间的气球，会改变左右邻居关系，导致局部最优解不一定导向全局最优。 | 判断中间的词义，受前后文影响，只看左边容易产生歧义。 |
| **解法核心** | **分治思想**：将大问题拆解成最后戳破哪个气球。假设最后处理`k`，则`k`不受区间内其他气球的影响，其左右边界固定为整个区间的边界。 | **双向结构**：将序列处理拆成正向和反向两个流。当前时刻的隐状态由前后文共同决定。 |
| **信息利用** | 为了计算 `dp[i][j]`，需要知道 `dp[i][k-1]` (左边) 和 `dp[k+1][j]` (右边)。 | 为了计算 `h_t`，需要知道 `h_{t-1}` (正向历史) 和 `h_{t+1}` (反向未来)。 |
| **依赖关系** | **区间依赖**：小区间的结果依赖更小区间。最终依赖整个数组的边界（虚拟的1）。 | **序列依赖**：当前步的结果依赖前后步。最终依赖整个句子。 |
| **为什么有效** | 通过**枚举最后戳破的气球**，消除了后效性。 | 通过**拼接双向表示**，引入了未来信息，消除歧义。 |

### 3. 一个有趣的“点球”比喻

为了帮你更好地理解这种思维上的相似性，可以想象这样一个场景：**点球大战**。

-   **单向LSTM / 常规思维**：
    你是一个守门员，球踢过来你才扑救。你只能根据**球飞过来的轨迹（过去的信息）**来判断方向。如果球在空中突然变向（相当于序列中的歧义），你可能会扑错。

-   **Burst Balloons 解法 / BiLSTM 思维**：
    假设你是上帝视角，你知道球最终会飞向**左上角（未来信息）**。
    那么，你会预先判断：为了让球飞向左上角，它现在必须经过哪些路径点？
    你通过**结合起点（过去）和终点（未来）**，准确地预判了球的轨迹。

### 4. 具体映射：把 Burst Balloons 公式“翻译”成 BiLSTM

Burst Balloons 的标准解法公式是：
`dp[i][j] = max(dp[i][j], dp[i][k-1] + dp[k+1][j] + nums[i-1] * nums[k] * nums[j+1])`

我们可以把它“翻译”成 BiLSTM 的语言：

-   `dp[i][j]`：表示处理从句子第 `i` 词到第 `j` 词这个片段，能获得的最佳语义理解。
-   `nums[k]`：当前要重点分析的词 `k` 本身的含义（词向量）。
-   `nums[i-1]`：正向LSTM传来的上文信息（左边的邻居）。
-   `nums[j+1]`：反向LSTM传来的下文信息（右边的邻居）。
-   `nums[i-1] * nums[k] * nums[j+1]`：**这就是 BiLSTM 的核心操作——将当前词与前后文的表示进行融合（拼接或加权），得到一个融合了上下文的增强表示。**
-   `dp[i][k-1]` 和 `dp[k+1][j]`：处理左半句和右半句的语义。

### 总结

你能把这两个看似无关的领域联系起来，说明你抓住了它们共同的本质：**当一个决策（或一个词）的最终价值取决于其左右两侧的上下文时，传统的单向遍历（或贪心）是失效的。必须采用一种能够同时“看到”左右两侧信息的视角——无论是通过双向网络结构，还是通过枚举最后动作的区间分治——才能做出最优判断。**

### 🚀 方案一：配置国内镜像源（最推荐）

这是最简单有效的方法。通过修改Ollama的配置，让它从一个国内的、速度更快的服务器上下载模型。

**操作步骤如下：**

1.  **找到配置文件**：Ollama的配置文件通常在你用户目录下的 `.ollama` 文件夹里，文件名叫 `config.json`。在Linux或macOS系统上，完整路径一般是 `~/.ollama/config.json`。如果文件或目录不存在，可以自己手动创建一个。
2.  **修改配置**：用任何文本编辑器打开这个文件，在里面添加或修改 `"registry"` 这个字段，让它指向一个可用的国内镜像地址。

```json
{
  "registry": "https://<你的镜像源地址>"
}
```

3.  **可用的镜像源**：根据我查到的信息，以下地址是网友验证过可以使用的，你可以试试看：
    *   **CNB.cool提供的镜像**：`https://cnb.cool/hex/ollama` [citation:6]。这是一个专门为国内用户优化的项目，速度不错[citation:6]。
    *   **阿里云镜像（Docker场景）**：如果你是用Docker部署的Ollama，可以尝试使用阿里云的镜像加速器地址，比如 `registry.cn-hangzhou.aliyuncs.com/ollama/ollama` [citation:1]。
    *   **其他社区镜像**：网络上还有其他一些社区维护的镜像，你可以在技术社区搜索“Ollama 国内镜像”获取最新可用的地址[citation:2][citation:9]。

4.  **重启Ollama**：修改完配置文件并保存后，**必须重启Ollama服务**（如果是命令行直接运行的，可以按 `Ctrl+C` 终止再重新运行；如果是后台服务，需要重启服务），新的配置才会生效。

### 💡 方案二：使用代理

如果你的网络环境有代理（如Clash、V2Ray等），可以给Ollama的下载进程设置代理。

*   **临时设置**：在要执行 `ollama pull` 的终端窗口中，先运行下面的命令（以HTTP代理为例，端口按你的实际情况修改）：
    ```bash
    export https_proxy=http://127.0.0.1:7890
    export http_proxy=http://127.0.0.1:7890
    ```
    然后再执行你的 `ollama pull` 命令[citation:2][citation:7]。这种方式只在当前终端窗口有效。

*   **永久设置**：如果你用的是Linux或macOS，可以把上面的 `export` 命令加到你的shell配置文件中（比如 `~/.bashrc` 或 `~/.zshrc`），这样每次打开终端都会自动生效。

### 📦 方案三：手动下载模型文件（备选方案）

如果上面两种方法都不太适合你，也可以手动把模型文件下载下来，再让Ollama加载。

1.  **寻找下载源**：很多AI社区和平台（比如 **ModelScope 魔搭社区**）都提供了模型的国内下载地址[citation:2][citation:9]。你需要先找到你想要的那个模型（例如 `qwen3.5:35b`）的 `.gguf` 格式文件。
2.  **下载并创建模型**：
    *   使用下载工具（浏览器、迅雷、`wget` 或 `aria2c` 等）把模型文件下载到你的电脑上。
    *   在模型文件所在目录，创建一个名为 `Modelfile` 的文本文件，里面写入一行内容：`FROM ./你下载的模型文件名.gguf`。
    *   打开终端，进入该目录，运行下面的命令来创建一个Ollama模型：
        ```bash
        ollama create 你想给模型起的名字 -f ./Modelfile
        ```
    *   之后，你就可以用 `ollama run 你想给模型起的名字` 来运行它了[citation:2]。

### ⚡ 进阶：使用多线程下载工具

如果你的网络仍然不够稳定，可以考虑先用 `aria2c` 这样的多线程下载工具，手动将模型文件下载下来。

*   **原理**：`aria2c` 可以通过多线程、分块的方式下载，能有效提升下载速度和稳定性[citation:3][citation:5]。
*   **步骤**：首先，你需要通过一些方法（比如查看Ollama的日志）获取到模型文件的真实下载URL，然后使用类似 `aria2c -x 16 -s 16 -k 1M "模型的下载URL"` 的命令进行下载。下载完成后，再参考**方案三**的方法让Ollama加载这个文件[citation:3]。
