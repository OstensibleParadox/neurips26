ssl_connection_error是什么意思
**SSL connection error** 的意思是 **SSL 连接错误**。

简单来说，这是你的浏览器（或客户端）与网站服务器在尝试建立安全连接时失败了。SSL（Secure Sockets Layer，安全套接层）及其后继者 TLS（Transport Layer Security，传输层安全）是负责在网络两端建立加密通道的协议，当这个“握手”过程出现问题时，就会报这个错误。

### 常见原因及解决方法

你可以按以下顺序排查：

**1. 系统时间不正确**
这是最常见的原因。SSL 证书有严格的有效期。如果你的电脑或手机时间（尤其是年份）与真实时间相差过大，系统会认为证书已过期或尚未生效。

-   **解决**：检查并校准设备的时间，开启“自动设置时间/与互联网时间同步”。

**2. 网络环境问题**
某些公共 Wi-Fi、公司内网或 VPN 需要先登录认证（如强制门户），或者防火墙拦截了关键数据包。

-   **解决**：尝试切换网络（如切换到手机热点）。如果使用了 VPN，可尝试断开或更换节点。

**3. 浏览器或缓存问题**
过时的浏览器版本可能不支持服务器要求的新加密协议，而损坏的缓存或 Cookie 也可能干扰连接。

-   **解决**：清除浏览器缓存和 Cookie，或尝试使用无痕/隐私模式访问。也可尝试更换浏览器。

**4. 安全软件或防火墙干扰**
某些杀毒软件或防火墙会扫描 HTTPS 流量，用自己签发的证书替换原站证书，如果配置不当就会报错。

-   **解决**：暂时禁用杀毒软件或防火墙进行测试。

**5. 网站自身问题**
可能是网站的 SSL 证书已过期、未被信任的机构签发（如自签名证书），或域名与证书不匹配。

-   **解决**：如果你是网站访问者，可以联系网站管理员反映情况。如果你是自己网站的站长，则需要更新或重新配置 SSL 证书。

### 不同场景下的提示
-   **浏览器**：通常显示“您的连接不是私密连接”或“NET：ERR_CERT_*”类错误。
-   **手机 App**：可能显示“网络错误”或“无法连接到服务器”。
-   **Git/curl 等命令行工具**：会明确提示 SSL certificate problem。

**4. 服务器端问题**
如果只有特定某个网站打不开，而其他网站正常，通常是该网站的 **SSL 证书过期、配置错误**，或使用了不安全的加密协议（如 TLS 1.0）。
-   **解决**：这种情况你无法处理，只能等待网站管理员修复，或尝试在浏览器中点击“高级”->“继续前往（不安全）”临时访问（需确认网站可信）。

**5. 客户端过旧**
如果你的操作系统（如 Windows 7、旧版 Android）或浏览器版本太老，可能不支持服务器要求的最新 TLS 1.3 协议。
-   **解决**：更新操作系统或更换现代浏览器（Chrome、Edge 最新版）。

## 1. 连接被拒绝的错误类型

### ① `Connection refused`（连接被拒绝）
```
ssh: connect to host xxx.xxx.xxx.xxx port 22: Connection refused
```
**含义**：目标机器的 22 端口没有监听 SSH 服务。
**原因**：
- SSH 服务未启动
- 防火墙阻止了 22 端口
- SSH 服务监听在其他端口

### ② `Permission denied`（权限拒绝）
```
Permission denied (publickey,password).
```
**含义**：服务器收到了连接，但拒绝了你提供的认证信息。
**原因**：
- 用户名错误
- 密码错误
- SSH 密钥未添加
- 服务器禁用了密码登录，只允许密钥登录

### ③ `Connection timed out`（连接超时）
```
ssh: connect to host xxx.xxx.xxx.xxx port 22: Connection timed out
```
**含义**：客户端发起的连接请求没有得到任何响应。
**原因**：
- 网络不通
- 防火墙直接丢弃了数据包（而非返回拒绝）
- 服务器 IP 地址错误

### ④ `Host key verification failed`
```
Host key verification failed.
```
**含义**：服务器的主机密钥与本地 `known_hosts` 文件中记录的不一致。
**原因**：
- 服务器重装了系统
- 中间人攻击（较少见）
- 之前连接过同名 IP 的不同机器
