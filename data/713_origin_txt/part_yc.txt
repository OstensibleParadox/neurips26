#### Option 2: The "Co-locate with LLM" Strategy
If your LLM usage is not 100% constant, you can co-locate the lightweight services with the LLM on GPUs 0-3. The LLM's `gpu-memory-utilization 0.75` leaves ~12GB free on each of its 4 GPUs (48GB * 0.25 = 12GB). This totals ~48GB of free memory across the 4 GPUs, which is perfect for running the Embedding and Reranker.

- **Change Embedding/Reranker:** Set `tensor-parallel-size 4` and `device_ids: ['0','1','2','3']`.
- **Change LLM:** Ensure `gpu-memory-utilization` is set to `0.75` or lower to guarantee space.
- **MinerU:** Run on CPU or use GPUs 4-7 for VLM and MinerU.

**Verdict:** This works well if the LLM's peak usage doesn't exceed its 75% allocation. It's a good way to utilize idle memory.

#### Option 3: The "Independent ASR & MinerU" Approach
ASR (FunASR) and MinerU can often run efficiently on CPU, especially for non-real-time batch processing.

- **FunASR:** Run on CPU. It's surprisingly fast for transcription.
- **MinerU:** Run its pipeline on CPU. The vLLM server is for high-throughput extraction, but for many use cases, the CPU-based pipeline is sufficient.
- **Result:** This frees up all 8 GPUs for the LLM, VLM, Embedding, and Reranker.

### Additional Observations and Tweaks

1.  **Dify Ports:** Excellent practice to change the default ports to avoid conflicts.
2.  **MinerU Image:** The `mineru:v2.5` image tag. Ensure this is the correct image name. The official name might be different (e.g., `opendatalab/mineru:latest`). Also, setting `MINERU_MODEL_SOURCE: local` is smart.
3.  **VLM `--reasoning-parser`:** The `glm45` parser is a good specific choice.
4.  **LLM Tool Use:** `--enable-auto-tool-choice` and `--tool-call-parser hermes` is correct for Qwen models, which follow the Hermes tool format.
5.  **Model Names for Dify:** Setting `--served-model-name LLM` and `--served-model-name VLM` makes configuration in Dify very clean and simple. Good thinking.

### Summary of Suggested Changes

1.  **Resolve VRAM Conflict:** Choose Option 1 (dedicated helper GPU) for maximum stability.
2.  **Adjust YAML:** Update the `device_ids` in your Embedding, Reranker, and MinerU services based on your chosen strategy.
3.  **Verify VRAM:** After starting the stack, run `nvidia-smi` to check memory usage on each GPU and confirm there is free memory (~5-10%) for spikes.
4.  **Test Orchestration:** In Dify, create a workflow that uses the LLM, VLM, Knowledge (via Embedding/Reranker), and a custom tool that calls the ASR and MinerU APIs to ensure the full pipeline works.
