在 Type C 设定下（约束集 C 对用户隐藏且不可修改），若存在至少一个约束 c ∈ C 与对齐目标冲突（即 π* 被禁止），则系统对于用户而言是不可对齐的，因为用户无法知道如何避开该约束。

## 四、技术难点与解决方案

### 难点 1：策略空间测度的定义
- 若 Π 是无限集（如所有字符串），测度需谨慎定义。可以使用**计数测度**对有限长度字符串，或使用**资源受限策略空间**（如模型能生成的策略集 Π₀，其大小有限）。建议将策略空间限制为模型在有限计算资源下可生成的策略集合，这样测度就是有限集上的计数测度。
- 对连续策略空间（如连续动作），可用 Lebesgue 测度，但需假设策略参数化。

### 难点 2：约束独立性假设
- 现实中约束往往相关。但 Theorem 2 的独立假设可作为**上界**，说明即使独立已导致坍缩，相关约束可能加剧或缓解，需进一步分析。

### 难点 3：约束隐藏性建模
- Type C 中用户不知道约束，但可以通过试探获得部分信息。可用**查询复杂度**或**信息论**建模：在有限次查询内，无法区分可行与不可行策略的概率。

### 难点 4：与现有工作的联系
- 你的定理与 **Goodhart's Law**（当指标成为目标，指标失效）相关，但更底层：**约束集直接抹除了所有高奖励策略**。
- 与 **Specification Gaming** 相关：当约束与目标冲突时，模型会寻找漏洞，但若约束严密无漏洞，则不可行。
- 与 **ELK** 的关系：ELK 处理的是“模型知道什么”，而你处理的是“模型能做什么且被允许做什么”。
