在 `git init` 之后，将本地仓库提交到云端（如 GitHub、GitLab、Gitee 等）的步骤如下：

## 1. 在云端创建远程仓库

首先在 GitHub/GitLab 等平台上创建一个**新的空仓库**（不要勾选初始化 README、.gitignore 等选项）。

## 2. 关联本地仓库与远程仓库

在本地仓库目录下执行：

```bash
# 添加远程仓库地址（将 URL 替换为你的仓库地址）
git remote add origin https://github.com/用户名/仓库名.git

# 或者使用 SSH 方式（推荐）
git remote add origin git@github.com:用户名/仓库名.git
```

## 3. 添加文件并提交

```bash
# 查看当前状态
git status

# 添加所有文件到暂存区
git add .

# 提交到本地仓库
git commit -m "Initial commit"
```

## 4. 推送到云端

```bash
# 首次推送，需要设置上游分支
git push -u origin main

# 如果默认分支是 master，则使用
git push -u origin master
```

## 完整示例流程

```bash
# 1. 初始化本地仓库
git init

# 2. 添加文件
echo "# My Project" > README.md
git add README.md
git commit -m "first commit"

# 4. 推送到云端
git push -u origin main
```

ssl_connection_error是什么意思
**SSL connection error** 的意思是 **SSL 连接错误**。

简单来说，这是你的浏览器（或客户端）与网站服务器在尝试建立安全连接时失败了。SSL（Secure Sockets Layer，安全套接层）及其后继者 TLS（Transport Layer Security，传输层安全）是负责在网络两端建立加密通道的协议，当这个“握手”过程出现问题时，就会报这个错误。

### 常见原因及解决方法

你可以按以下顺序排查：

**1. 系统时间不正确**
这是最常见的原因。SSL 证书有严格的有效期。如果你的电脑或手机时间（尤其是年份）与真实时间相差过大，系统会认为证书已过期或尚未生效。

-   **解决**：检查并校准设备的时间，开启“自动设置时间/与互联网时间同步”。

**2. 网络环境问题**
某些公共 Wi-Fi、公司内网或 VPN 需要先登录认证（如强制门户），或者防火墙拦截了关键数据包。

-   **解决**：尝试切换网络（如切换到手机热点）。如果使用了 VPN，可尝试断开或更换节点。

**3. 浏览器或缓存问题**
过时的浏览器版本可能不支持服务器要求的新加密协议，而损坏的缓存或 Cookie 也可能干扰连接。

-   **解决**：清除浏览器缓存和 Cookie，或尝试使用无痕/隐私模式访问。也可尝试更换浏览器。

**4. 安全软件或防火墙干扰**
某些杀毒软件或防火墙会扫描 HTTPS 流量，用自己签发的证书替换原站证书，如果配置不当就会报错。

-   **解决**：暂时禁用杀毒软件或防火墙进行测试。

**5. 网站自身问题**
可能是网站的 SSL 证书已过期、未被信任的机构签发（如自签名证书），或域名与证书不匹配。

-   **解决**：如果你是网站访问者，可以联系网站管理员反映情况。如果你是自己网站的站长，则需要更新或重新配置 SSL 证书。

### 不同场景下的提示
-   **浏览器**：通常显示“您的连接不是私密连接”或“NET：ERR_CERT_*”类错误。
-   **手机 App**：可能显示“网络错误”或“无法连接到服务器”。
-   **Git/curl 等命令行工具**：会明确提示 SSL certificate problem。

ssl_connection_error是什么意思
**SSL_connection_error** 意思是 **SSL 连接错误**。

它是指你的客户端（如浏览器、APP）与服务器尝试建立 HTTPS 加密连接时失败了。简单来说，就是“安全通道没建起来”。

### 常见原因及解决方法

**1. 系统时间不正确**
SSL 证书有严格的有效期。如果你的设备时间（尤其是年份）与真实时间偏差过大，系统会认为证书已过期或未生效。
-   **解决**：检查并开启系统“自动设置时间/日期”。

**2. 网络环境干扰**
某些公共 WiFi、公司网络或 VPN 会拦截或篡改 SSL 连接，进行内容审查或注入广告。
-   **解决**：切换到手机热点（排除本地网络问题），或暂时关闭 VPN/代理软件测试。

**3. 杀毒软件/防火墙拦截**
部分安全软件会启用“SSL扫描”或“HTTPS保护”功能，用自己的证书替换真实网站证书，如果替换失败就会报错。
-   **解决**：暂时禁用杀毒软件，或在软件设置中关闭“HTTPS扫描/加密连接扫描”功能。

**4. 服务器端问题**
如果只有特定某个网站打不开，而其他网站正常，通常是该网站的 **SSL 证书过期、配置错误**，或使用了不安全的加密协议（如 TLS 1.0）。
-   **解决**：这种情况你无法处理，只能等待网站管理员修复，或尝试在浏览器中点击“高级”->“继续前往（不安全）”临时访问（需确认网站可信）。

**5. 客户端过旧**
如果你的操作系统（如 Windows 7、旧版 Android）或浏览器版本太老，可能不支持服务器要求的最新 TLS 1.3 协议。
-   **解决**：更新操作系统或更换现代浏览器（Chrome、Edge 最新版）。
