怎样使用pandoc把docx变成markdown
我们使用pandoc将docx转换为markdown的基本命令是：
   pandoc -f docx -t markdown 输入文件.docx -o 输出文件.md

 但是，根据具体的需求，我们可能还需要添加一些选项来优化转换结果，例如：
   - 设置markdown的格式风格（如gfm，plain等）
   - 处理图片（提取并保存到指定目录）
   - 调整标题级别等

 以下是一些常用的选项：

 1. 指定输出格式为markdown，可以使用`-t markdown`，但为了更现代的markdown格式（如GitHub Flavored Markdown），可以使用`-t gfm`。
 2. 如果需要提取docx中的图片，可以使用`--extract-media`选项，后面跟一个目录名，pandoc会将图片提取到该目录中。

 示例命令：
   pandoc -f docx -t gfm input.docx --extract-media=./images -o output.md

 这个命令将input.docx转换为GitHub风格的markdown，并将图片提取到当前目录下的images文件夹中。

 3. 调整标题级别：有时我们希望将文档中的标题级别进行调整，例如将一级标题改为二级标题，可以使用`--shift-heading-level-by=1`，这样所有标题级别都会增加1（即原一级标题变为二级，二级变为三级，以此类推）。如果减少级别，可以使用负数。

 4. 保留原始文档中的换行：默认情况下，pandoc会将段落转换为一行，如果希望保留换行，可以使用`--wrap=preserve`，但注意，markdown中段落内的换行通常需要两个空格或强制换行符。不过，在markdown中，我们通常不保留段落内的换行，因为markdown语法中段落是由空行分隔的。

 5. 如果希望得到更简洁的markdown，可以使用`--atx-headers`，这样标题会使用#样式，而不是带下划线的样式。

 6. 设置markdown的引用风格：`--reference-links`可以使用引用链接，这样链接会放在文档末尾，使文档更清晰。

 综合以上，一个更复杂的例子：

   pandoc -f docx -t gfm input.docx --extract-media=./images --shift-heading-level-by=0 --atx-headers --wrap=auto -o output.md

 但是，根据实际情况，您可能不需要所有选项。

 注意：pandoc的版本不同，可能支持的选项略有差异，可以使用`pandoc --help`查看所有选项。

 如果您的文档中有复杂的表格，转换后可能需要手动调整，因为markdown的表格格式有限。

 另外，如果文档中有公式，pandoc会尝试将它们转换为LaTeX格式，或者如果输出格式支持的话，也可以保留为LaTeX。对于markdown输出，公式会被转换为LaTeX代码。

 根据您的需求，选择适当的选项即可。
使用 Pandoc 将 DOCX 转换为 Markdown 有几种方法：

## 基本转换命令

```bash
# 最简单的转换
pandoc input.docx -o output.md

# 指定输出格式为 markdown
pandoc input.docx -t markdown -o output.md
```

## 常用选项和参数

```bash
# 转换为 GitHub Flavored Markdown (GFM)
pandoc input.docx -t gfm -o output.md

# 保留图片文件并指定图片保存路径
pandoc input.docx --extract-media=./images -o output.md

# 转换时保留原始换行（不合并段落）
pandoc input.docx --wrap=none -o output.md

# 设置标题样式为 ATX 格式（使用 # 号）
pandoc input.docx --atx-headers -o output.md

# 多个选项组合使用
pandoc input.docx -t gfm --extract-media=. --wrap=none -o output.md
```

## 处理中文文档

```bash
# 对于中文文档，可能需要指定编码
pandoc input.docx -t markdown --wrap=none -o output.md

# 或者保留原始空格
pandoc input.docx -t markdown --preserve-tabs -o output.md
```

## 批量转换

```bash
# 批量转换多个文件
for file in *.docx; do
    pandoc "$file" -t markdown -o "${file%.docx}.md"
done
```

## 高级用法

```bash
# 使用模板文件
pandoc input.docx --template custom.template -o output.md

# 添加 YAML 元数据块
pandoc input.docx --standalone -o output.md

# 只提取特定内容（如从第2节开始）
pandoc input.docx --toc-depth=3 -o output.md
```

3. **中文字符**：确保终端和文件编码一致（建议使用 UTF-8）

有没有obsudian风味markdown
我们通常所说的“Obsidian 风味 Markdown”主要是指 Obsidian 软件所支持的一些扩展语法，但请注意，Obsidian 基本上使用 CommonMark 标准，并添加了一些扩展功能（如双链笔记、标签等）。Pandoc 默认的 markdown 输出格式可能不完全符合 Obsidian 的要求，但我们可以通过调整参数来尽量接近。

 不过，需要注意的是，Obsidian 的一些特性（如内部链接格式、标签等）是 Obsidian 特有的，Pandoc 可能不会直接生成这些格式。但我们可以通过一些后处理来调整。

 下面是一些常用的转换设置，可以使得生成的 Markdown 更符合 Obsidian 的使用习惯：

 1. 使用 `-t markdown` 输出，但 Obsidian 支持多种 Markdown 扩展，我们可以尝试使用 `-t markdown+link_attributes` 等。不过，Obsidian 的内部链接格式是 `[[文件名]]` 或 `[[文件名#标题]]`，而 Pandoc 默认生成的链接是标准 Markdown 的 `[文本](链接)` 格式。所以，如果我们想要将文档中的链接转换为 Obsidian 的内部链接，可能需要进行额外的处理。

 2. 对于图片，Obsidian 使用标准的 Markdown 图片语法，但可能希望图片存放在指定的文件夹中。我们可以使用 `--extract-media` 选项来提取图片。

 3. 标题：Obsidian 使用 ATX 风格的标题（即用 # 号表示），所以我们可以使用 `--atx-headers` 选项。

 4. 表格：Obsidian 支持 GFM 表格，所以我们可以使用 `-t gfm` 来输出 GitHub Flavored Markdown，这样表格会以更兼容的方式输出。

 5. 任务列表：Obsidian 支持任务列表（- [ ] 和 - [x]），但是 Pandoc 在转换 docx 时可能会将复选框转换为普通字符，所以可能无法正确转换任务列表。这可能需要后续手动调整。

 由于 Pandoc 本身并不直接支持 Obsidian 的内部链接语法，所以如果你希望将文档中的超链接转换为 Obsidian 的内部链接（即双链），那么可能需要进行字符串替换。例如，将 `[文本](链接.md)` 替换为 `[[链接.md|文本]]` 或 `[[链接.md]]`（如果文本和链接名相同）。

 但是，请注意，Pandoc 转换 docx 时，链接可能被转换为各种形式，因此这种替换可能不总是准确的。

 因此，一个比较现实的做法是：先使用 Pandoc 将 docx 转换为标准的 Markdown（尽量接近 GFM），然后在 Obsidian 中打开，并利用 Obsidian 的功能进行内部链接的创建。

 下面给出一个转换命令示例，它结合了上述的一些选项：

```bash
pandoc input.docx \
  -t gfm \                          # 输出 GitHub Flavored Markdown
  --atx-headers \                   # 使用 ATX 风格的标题
  --wrap=none \                     # 不自动换行，保持原文档的换行
  --extract-media=./attachments \   # 提取媒体文件到 attachments 文件夹
  -o output.md
```

 注意：`-t gfm` 已经包含了表格和任务列表等扩展，但是否能正确转换任务列表取决于原文档的复选框是否被正确识别。实际上，Pandoc 在转换 docx 时，对于复选框可能会转换为 Unicode 符号，而不是任务列表的语法。因此，你可能需要手动替换。

 另外，Obsidian 支持标记（如 `#tag`），但 Pandoc 不会自动生成这些。你可以在转换后手动添加，或者如果你有固定的元数据（如标签）可以通过 Pandoc 的元数据块添加，但 Obsidian 的标签是放在正文中的（以 `#` 开头），所以你可能需要将文档的某些部分（如关键词）转换为标签。

 总结：使用上述命令可以得到一个基础版本，然后你可能需要根据 Obsidian 的特性进行一些手动调整。对于大规模转换，你可能需要编写脚本进行后处理，例如将标准 Markdown 链接替换为 Obsidian 内部链接，但前提是你能识别出哪些是内部链接（通常是以 .md 结尾的链接）。

 另外，Obsidian 还支持笔记之间的内部链接，通常我们使用 `[[笔记名称]]` 或 `[[笔记名称#标题]]`。如果你希望将文档中的链接转换为这种形式，你可以使用正则表达式进行替换。但请注意，这可能会误伤一些外部链接。

 例如，你可以使用如下命令（Linux/Mac 下使用 sed，Windows 下可能需要使用其他工具）进行替换：

```bash
# 将 [文本](链接.md) 替换为 [[链接.md|文本]]
sed -E 's/\[([^]]+)\]\(([^)]+\.md)\)/\[\[\2\|\1\]\]/g' output.md > output_obsidian.md
```

 但请注意，这个正则表达式非常基础，可能无法处理链接中包含空格或括号的情况，也可能误伤一些图片链接（图片链接也是同样的语法，但图片链接以 ! 开头）。因此，更复杂的替换可能需要更精细的处理。

 总之，转换过程可能需要根据具体文档进行调优。
Obsidian 确实有一些特有的 Markdown 风味和语法扩展。虽然 Pandoc 默认的 Markdown 输出不是完全针对 Obsidian 优化的，但可以通过参数调整来接近 Obsidian 的风格。
